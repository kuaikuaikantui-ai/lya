# 源体检报告（2026-11-21，实测于用户本地网络 + 结合 CF 后端现状）

> 探测方法：curl 直连（8-12s 超时、Chrome UA），测连通性/延迟/返回数据校验。
> 注意：本机网络≈用户设备网络；Cloudflare Worker 侧的可达性以生产环境表现为准（用户反馈视频源"已经做得很好"= CF→各源基本通）。两份名单用途不同：
> - **服务端聚合**（`/api/*` 由 CF 转发）：以 CF 可达为准，几乎全通 → 保留大库源，但必须加健康分避免拖慢响应。
> - **客户端直连兜底**（静态托管/APP 直连模式）与 **m3u8 播放**（用户设备直接拉流）：本机探测名单才是关键。

### 📋 修复项
1. `functions/api/[[path]].js` 中无尽/光速的 base URL 去掉 `/from/xxx` 前缀（404 → 200 已实测验证正确路径）。
2. 健康分机制：连续失败≥2 的源本轮跳过（KV 缓存 10 分钟），成功后恢复；每源 EMA 延迟记录。
3. 聚合竞速改"提前退出"：前 N 个源出结果即返回，剩余后台继续。

## 五、给频道分类体系的直接结论

- 分类数据源优先级：**CMS ac=list 实时分类表**（金鹰/360/MD/百度/极速/无尽均返回 `class` 数组）→ 归一化为频道（电影/电视剧/综艺/动漫/短剧）+ 子分类（动作/喜剧/爱情/科幻/悬疑/都市/古装…）。
- 豆瓣作为榜单/评分增强（豆瓣高分、年度榜单、热门标签），失败静默降级不阻塞主流程。
- 短剧频道：qingtian 配置含 6 个短剧源（番茄/YY短剧/星芽短剧/东梨短剧/量子影视/非凡影视），上下滑流后续可从这里扩容。
