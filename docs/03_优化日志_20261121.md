## R1 · 长按倍速卡顿修复（用户痛点 #1）

根因分析（video.js + iOS 壳）：
1. 380ms 激活延迟 + `playbackRate` 切换时 WebKit 音频管线重配；
2. HUD 首次绘制使用 `backdrop-filter: blur` 强制快照整层视频合成（按下瞬间掉帧主因之一）；
3. 8.5s 卡顿看门狗可能在长按期间销毁重建整个播放器（`triggerAutoSwitchRoute`）；
4. 播放器换线重建后旧长按闭包误恢复新播放器倍速；
5. 原生壳 `setInterval(purgeAds, 1200)` 每 1.2s 全页 DOM 扫描抢占主线程；
6. 松手合成 click 触发 DPlayer 控制条 toggle（松开"卡一下"观感来源）。

修复（`video.js`）：
- 激活延迟 380→260ms；HUD 常驻 DOM，`opacity/transform` 合成器动画替代 `display` 切换，移除移动端 backdrop-filter；
- `window._lyaSpeedBoostActive` 门控：长按期间 `triggerAutoSwitchRoute` 直接跳过（已单测验证）；
- `switchPlayGroup` 重建播放器前重置长按状态；
- 恢复原速放 rAF 下一帧错峰；松手后 400ms 内捕获阶段屏蔽合成 click；
- 触感反馈接入原生桥 `nativeHaptic`（Safari 端自动回退 `navigator.vibrate`）。
- 补全避坑红线四要求的统一全屏调度 `window.toggleLyaFullscreen(action)`（原先引用未定义）。

修复（`ios/Lya/ContentView.swift`）：
- 广告清理改 MutationObserver 定向清除（600ms 去抖），移除 1.2s 轮询；
- 新增 `nativeHaptic`（UIImpactFeedbackGenerator/UINotificationFeedbackGenerator）与 `nativeScreenSleep` 桥；
- 屏幕常亮改为"仅视频播放期间"（播放器开/关时由网页层通知，`video.js` 已接线）；
- 新增加载失败原生重试面板（无离线包时）、`prompt()` 支持、UA 使用真实系统版本（保留 `LyaNativeApp` 标识）；
- 删除 `ios/Lya/SeekFrames/` 28 张死资源（-120KB）。

验证：合成触摸事件实测 touchstart→420ms→rate=2.0/HUD opacity=1；touchend→rate=1/HUD opacity=0；看门狗抑制单测通过。

## 用户反馈轮 4（官方源黑屏 / 4K 线路 / 加载速度）—— 全链路诊断与对策

**全链路诊断**（真实 ticket 直调 kanju 签名 API）：
1. 第三方聚合 CDN（原站·红牛/新浪等）m3u8 主清单可达（200），但**分片在 :65 等非标端口且用户侧拉流仅 92KB/s**——播 1080P 远不够 → 黑屏/卡死。
2. 部分官方源 m3u8 为 **AES-128 加密**（enc.key 无防盗链可拉 ✓），排除 key 防盗链因素。
3. kanju line_options 全貌实测：**9 条官方凭证线路（1080P-官方V/S/D/Z、专享4K-Y 等）+ 21 条第三方直连**；官方凭证换直连返回 **HTTP 401（需原站会员授权）**——这就是"4K/官方R·字节CDN 消失"的真相（我们匿名调用被拒，原站 APP 有会员态）。
4. kanju API CORS：预检 204 但**无 access-control-allow-origin 头** → 浏览器跨域一律拦截 → 前端直调方案不可行（原站 APP 原生 fetch 无此限制）。

**对策落地**：
- **kanju.js 原站直连客户端**（前端签名直调架构，本机实测被 CORS 拦截后保留为后续验证通道；若 kanju 未来放开 CORS 即生效）
- **后台静默测速优选**：播放后 800ms 对当前线路 + 前 6 条备选做真实拉流测速（主清单+首分片），当前线路受阻时**自动切到实测最快备选**（比 10s 看门狗快得多）
- 起播看门狗 10s → **6s**
- 已知边界：官方 4K/CDN 线路需原站会员授权（401），无法绕过；第三方 CDN 的"慢"源于其 CDN 对用户网络的分发质量，后台测速优选会把最快可用线路自动顶上。

## 用户反馈轮 6（官方源黑屏的根治方案：kanju 原生解析桥）—— 提供账号登录验证后落地

用户提供原站账号授权测试。**登录机制完整逆向成功**：

**根治方案（本轮已实现）**：对齐原站 H5Shell 架构——
1. iOS 壳新增隐藏 WKWebView（加载 kanju32.com，游客 Cookie 自动建立），注入带签名的同源 fetch 桥函数；

3. kanju.js 的 KanjuClient 改造：APP 内优先走原生桥，网页端静默回退后端链路（CORS 所限）；
4. 官方线路组动态追加（1080P-官方V/S/Z、专享4K-Y 等置顶），播放时按需解析对应集。
预期效果：APP 内官方字节 CDN 线路解锁（原站同款速度与 4K），线路抽屉可见"原站官方·1080P-官方V"等组。
